# DressCodeJS

DressCodeJS – это методология построения архитектуры JavaScript-приложений и утилита сборки JS-кода, написанного по этой методологии.

Согласно DressCodeJS, приложение состоит из классов и статических объектов, содержащих вложенные классы, объекты или самостоятельные функции. И классы, и статические объекты именуются в CamelCase-стиле (это важно, иначе сборка не будет работать). Каждый класс/объект лежит в своём файле с именем, совпадающем с именем класса/объекта. Если объект содержит другие классы, которые, соответственно, должны лежать каждый в своём файле, то имя корневого объекта совпадает с именем папки, в которой содержатся вложенные классы. Кроме того, в папке обязательно должен быть файл index.js, в котором описывается корневой объект.

Наконец, пример. Имеем такую структуру файлов

    + js-libs    
    |-- + MyProject
        |--+ Forms
        |  |--- index.js
        |  |--- Abstract.js 
        |--- index.js
        |--- App.js

И примерное содержимое.

js-libs/MyProject/index.js:

    var MyProject = {};

js-libs/MyProject/App.js:

    MyProject.App = Bricks.inherit({
        constructor: function() {
            this._form = new MyProject.Forms.Abstract();
        }
    });

js-libs/MyProject/Forms/index.js:

    MyProject.Forms = {};

js-libs/MyProject/Forms/Abstract.js:

    MyProject.Forms.Abstract = Bricks.inherit();

[Bricks](http://github.com/Kolyaj/Bricks) – библиотека базовых классов и функций, написанная в терминах DressCodeJS.

Теперь, имея такую структуру файлов, если мы где-либо вызовем `new MyProject.App()` и соберём файл утилитой dresscodejs, то в результирующий файл попадут все вышеописанные файлы. А если вызовем `new MyProject.Forms.Abstract()`, то подключатся все файлы, кроме MyProject/App.js, т.к. он нигде не используется. И в обоих случаях подключится кусок файла Bricks/index.js, в котором описана функция `Bricks.inherit`, но об этом позже.

В вышеприведённом примере в директории js-libs рядом с MyProject могут лежать и другие папки с исходниками, например, папка OtherProject в которой будет описан корневой объект `OtherProject`.

Директория js-libs в данном примере называется библиотека, и таких библиотек в проекте может быть несколько. Директория становится библиотекой после того, как она будет описана в файле .dresscode, который состоит из строк, в каждой относительный путь до одной библиотеки. Файл .dresscode обычно один на весь проект. Можно больше, но нет смысла, только путаницы добавит. .dresscode это обычный текстовый файл, в котором одна строка – один относительный путь до библиотеки. Утилита DressCodeJS перед сборкой очередного файла ищет соответствующий этому файлу .dresscode: сначала в директории собираемого файла, затем на директорию выше, и так далее.

Важно то, что в библиотеках нет запускаемого кода, только описания классов и функций. Если собрать какой-нибудь библиотечный файл со всеми зависимостями и подключить его на страницу, то ничего не произойдёт. Нужно создать папку, в которой будут лежать скрипты, подключаемые на страницы сайта. И уже в этих файлах будет находиться создание всех необходимых объектов, их первоначальная настройка и добавление их в нужные части страницы. В дальнейшем, при выкладке сайта, все скрипты из этой папки нужно будет собрать утилитой `dresscodejs` и выложить на сервер. Но при разработке проще использовать прокси-сервер [Yaxy](https://github.com/Kolyaj/Yaxy), чтобы налету собирать нужные файлы.

Скорее всего, вам понадобятся внешние библиотеки, написанные в терминах DressCodeJS. Такие библиотеки нужно подключить в проект с помощью npm, записав их в devDependencies, и записать путь до библиотеки в файле .dresscode.

При создании нового проекта в части работы с DressCodeJS нужно сделать несколько простых вещей:

1. Установить dresscodejs через npm в devDependencies.
2. Создать директорию, в которой будут лежать подключаемые на страницы js-файлы, обычно это static/js-dev.
3. Создать библиотечную директорию, обычно это static/js-libs.
4. В корте проекта создать файл .dresscode и записать в нём путь до static/js-libs.
5. Если есть зависимости, то установить их через npm в devDependencies и указать путь до них в файле .dresscode.
6. Настроить [Yaxy](https://github.com/Kolyaj/Yaxy) для сборки js-файлов на лету.
